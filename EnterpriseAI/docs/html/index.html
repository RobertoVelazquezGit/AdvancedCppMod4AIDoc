EnterpriseAI

Educational C++ project demonstrating local simulations of distributed task scheduling and data processing, with source documentation generated by Doxygen. The Visual Studio solution is ../Mod4AIDoc.sln; its application project is EnterpriseAI.

Overview

Both main classes belong to the DistributedComputing namespace. The application uses simulated worker descriptions and ordinary local data. It does not connect to remote machines, start background workers, or implement a distributed runtime.

Main classes

  • TaskScheduler: a header-only class template that registers simulated workers, selects them in round-robin order, and returns futures for local callable tasks.
  • DistributedDataProcessor: a class that transforms vectors and divides byte buffers into partitions. Its template method is defined in the header; other methods are in the .cpp.

Main features and mock limitations

  • Worker registration rejects duplicate identifiers and invalid resource values.
  • Scheduler futures and data-processing futures use deferred execution. Calling get() or wait() performs the work on the calling thread.
  • Task exceptions are stored in the future and rethrown by get().
  • Worker selection is round-robin bookkeeping only. Other balancing policy values fall back to round robin.
  • CPU load and submitted-task counts provide local demonstration metrics.
  • Byte partitions use an inclusive start offset and an exclusive end offset.
  • Redistribution assigns worker names cyclically in metadata. It does not move data over a network; positive capacity magnitudes do not affect the assignment.
  • Retry, timeout, compression, parallelism, serialization, optimization, and replication options are reserved or descriptive. No real fault tolerance exists.

Basic usage

#include "TaskScheduler.h"
#include "DistributedDataProcessor.h"
#include <functional>
using namespace DistributedComputing;
using Scheduler = TaskScheduler<std::function<int()>, int>;
Scheduler scheduler(Scheduler::SchedulingPolicy{});
Scheduler::WorkerNode worker;
worker.nodeId = "worker-1";
scheduler.registerWorkerNode(worker);
auto answer = scheduler.scheduleTask([] { return 6 * 7; });
int value = answer.get(); // 42; execution occurs here.
DistributedDataProcessor processor(DistributedDataProcessor::ProcessingConfig{});
auto squares = processor.processDistributed<int>(
{1, 2, 3, 4}, [](const int& item) { return item * item; });
auto results = squares.get(); // 1, 4, 9, 16.

Requirements and build

  • Visual Studio with the MSVC v143 C++ toolset and a Windows SDK.
  • Debug x64 is the verified configuration and explicitly selects C++17.
  • Doxygen and Graphviz (dot) on PATH for documentation generation.

Open ../Mod4AIDoc.sln, select Debug / x64, and build and run EnterpriseAI. The example prints a task result of 42, batch results of 10 20, squared values of 1 4 9 16, and three partitions assigned to two simulated workers.

Generate and browse documentation

Run from the EnterpriseAI project directory, where Doxyfile and this README are located:

doxygen Doxyfile

Open docs/html/index.html. This README becomes the main page. Documentation includes public and documented private members, template parameters, source browsing, and Graphviz class, collaboration, include, call, and caller graphs where Doxygen can resolve the relevant relationships.

The configuration follows ../GuideDoxy.md, including recursive source scanning, Markdown input, HTML output, and no LaTeX output. Doxygen 1.18 no longer accepts the guide's legacy CLASS_DIAGRAMS option; HAVE_DOT and CLASS_GRAPH provide the supported class diagrams. Graphviz is found through PATH.

Generation diagnostics are written to docs/doxygen-warnings.log. After editing source comments or this README, run the same command again and refresh the HTML page. Source comments use English /// Doxygen documentation.
